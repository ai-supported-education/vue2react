# Правила работы Codex в учебном репозитории

## Режим прохождения

Если пользователь проходит активную сессию, scope определяется её README, DONE и rubric.

- Не изменяйте решение во время review.
- Не расширяйте обязательный scope соседними рефакторингами.
- Не открывайте следующую сессию до session:finish.
- Не показывайте правильные ответы quiz до явного запроса rescue level 3.
- Не применяйте reference solution автоматически.

## Review

1. Выполните pnpm session:check.
2. Получите пакет через pnpm session:review.
3. Проверьте только условия текущей карточки.
4. Верните PASS или NEEDS_WORK с доказательствами.
5. Запишите verdict командой pnpm session:review --record PASS или NEEDS_WORK только после фактической проверки.

PASS означает, что все обязательные критерии выполнены. Неблокирующие идеи перечисляются отдельно и не мешают завершить сессию.

## Подсказки

Подсказки выдаются по одной командой pnpm session:hint. Команда сама определяет
следующий уровень по progress; не извлекайте следующие уровни из branch
course-support без явного запроса пользователя.

## Режим разработки курса

Если пользователь просит создавать или менять сам тренажёр, разрешены обычные изменения кода и документации. Starter должен сохранять целевую ошибку, а acceptance test обязан:

- падать на starter по ожидаемой причине;
- проходить после минимального корректного решения;
- проверять пользовательское поведение, а не внутреннее устройство компонента.

После генерации или существенного изменения learner-facing материала выполните
обязательный независимый content-review:

1. Соберите packet через `pnpm author:content-review session <id>`.
2. Запустите отдельного subagent с `fork_turns="none"`. Не передавайте ему историю
   генерации, авторские рассуждения, hints или reference solution. Quiz key может
   находиться только во второй фазе packet как acceptance evidence.
3. Reviewer сначала читает `01-blind.md` и фиксирует понимание как учащийся, затем
   открывает `02-consistency.md`, проверяет rubric, tests и соседние карточки.
4. Reviewer работает read-only и возвращает `PASS` или `NEEDS_REWRITE` по формату
   packet. Родительский агент сохраняет report и записывает фактический verdict.
5. При `NEEDS_REWRITE` исправьте материал и повторите проверку новым fresh subagent.

После завершения всех карточек module обязателен такой же review командой
`pnpm author:content-review module <id>`. Материал не считается реализованным и не
публикуется без актуальных session PASS и module PASS.
