# Стандарт учебного материала

Сессия считается реализованной не по факту существования README, а только после content review по этому стандарту.

## Обязательная структура

Каждый учебный README содержит:

1. Измеримый результат сессии.
2. Объяснение ментальной модели, а не только описание API.
3. Минимум два исполнимых или мысленно исполнимых примера кода для code-темы.
4. Пошаговый data flow, timeline или таблицу там, где важен порядок.
5. Сравнение с Vue 3 Composition API.
6. Явную границу аналогии с Vue.
7. Разбор минимум двух типичных ложных решений.
8. Точное задание с перечисленными ограничениями.
9. Отдельное описание автоматического check и Codex-review.
10. Проверяемый список DONE.

Теоретическая часть должна занимать примерно 10–15 минут внимательного чтения. Если тема требует больше, она делится на несколько сессий.

## Карта понятий

У каждой сессии в `course.json` обязательны:

- `requires` — concept ids, доступные из входных знаний или предыдущих карточек;
- `introduces` — новые понятия, которые эта карточка обязана полноценно объяснить;
- `defers` — названные, но намеренно отложенные понятия, которые вводятся позже.

Manifest validation отклоняет неизвестный prerequisite, повторное introduction и
deferred concept, который нигде не вводится. Эти поля используются independent
content-review, чтобы отличать реальный пробел от явно отложенной темы.

## Практика

- Starter содержит одну целевую проблему.
- Acceptance test падает на starter по описанной причине.
- Минимальное корректное решение делает test зелёным.
- Test проверяет наблюдаемое поведение, а не имя hook или структуру реализации.
- Архитектурные ограничения проверяются rubric и Codex-review, а не хрупким source-code matching.

## Quiz

- `quiz.json` хранит только машиночитаемые ids, варианты и настройки проверки.
- У каждого quiz есть читаемый `quiz.md` с самодостаточным фрагментом кода,
  наблюдаемым порядком действий и вопросом для каждого пункта.
- Текстовый сценарий без кода допустим только там, где предмет вопроса нельзя
  выразить кодом; тогда он должен содержать явный data flow или схему.
- Вопрос не требует угадывать отсутствующий контекст: все важные исходные
  значения, props и действия пользователя показаны рядом.

## Подсказки и ответы

- Hints, quiz keys и reference solutions не лежат в рабочем дереве основной ветки.
- Support content хранится в отдельном Git ref course-support.
- Команда session:hint раскрывает только следующий уровень и записывает факт раскрытия в progress.
- Нельзя запросить сразу level 2 или 3.
- Level 1 напоминает концепцию.
- Level 2 указывает проблемную область.
- Level 3 показывает структуру исправления или reference fragment.
- Runner никогда не применяет reference solution автоматически.

Локальный пользователь технически может намеренно прочитать Git ref. Цель механизма — исключить случайное раскрытие в IDE и обычной навигации, а не строить криптографическую защиту от владельца repository.

## Проверка

Автоматическая проверка отвечает за воспроизводимые факты:

- quiz answer key;
- TypeScript;
- unit/integration tests;
- lint и архитектурные ограничения;
- build и E2E.

Codex-review отвечает за смысл, который нельзя надёжно выразить тестом:

- качество объяснения;
- соответствие React-модели;
- отсутствие обхода учебной цели;
- FSD ownership;
- разумность публичных контрактов.

Сессия с check review не может завершиться без актуального PASS, записанного после последнего автоматического check.

## Независимый content-review автора

Learner `session:review` и author content-review решают разные задачи. До публикации
каждой новой или существенно изменённой карточки отдельный subagent без истории
генерации выполняет два прохода:

1. blind learner-pass по learner-facing материалу;
2. consistency-pass по manifest, rubric, acceptance tests и соседним карточкам.

Reviewer не меняет файлы и не читает `course-support`. `PASS` допустим только без
BLOCKER и MAJOR findings. После исправлений старый content hash считается
устаревшим, а повторный review выполняет новый fresh subagent. После session-level
PASS обязателен интеграционный module-level PASS.

Полный протокол находится в [content-review-protocol.md](content-review-protocol.md).
