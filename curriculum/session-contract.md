# Контракт учебной сессии

## Основное правило

Сессия — минимальная завершённая единица курса. Тематический раздел может занимать несколько часов, но никогда не является одной задачей.

Каждая сессия:

- рассчитана на 30–60 минут;
- начинается с компилируемого и проходящего исходного состояния;
- вводит или закрепляет одну основную идею;
- имеет наблюдаемый результат и однозначный критерий `DONE`;
- заканчивается зелёными обязательными проверками;
- не оставляет обязательный TODO для следующей сессии;
- создаёт checkpoint, от которого можно безопасно продолжить позже.

Если автор курса не может пройти сессию за 60 минут без готового решения, сессия должна быть разделена.

## Внутренняя структура

Ориентир для одной сессии:

1. 5–10 минут — объяснение React-модели и, где уместно, сравнение с Vue.
2. 20–35 минут — одно упражнение.
3. 5–10 минут — автоматические проверки, Codex-review и фиксация результата.

Дополнительное улучшение не добавляется в конец текущей сессии как «небольшой бонус». Оно становится отдельной карточкой со своим результатом.

## Green-to-green

Исходное и конечное состояния сессии должны быть рабочими. Намеренно падающий тест может быть частью упражнения, но он ограничен текущей карточкой и должен стать зелёным для завершения.

Сессия не может заканчиваться состоянием:

- проект не собирается;
- следующий шаг обязан исправить текущий код;
- часть обязательной функциональности обозначена TODO;
- решение зависит от скрытого ручного действия, не описанного в критерии `DONE`.

## Проверка Codex

Codex проверяет только scope текущей карточки и возвращает:

1. `PASS` или `NEEDS_WORK`.
2. Доказательства по каждому обязательному критерию.
3. Минимальный список блокирующих исправлений.
4. Неблокирующие наблюдения отдельно, без расширения scope.

Codex не изменяет решение во время review. Помощь выдаётся по явному запросу тремя уровнями:

1. концептуальная подсказка;
2. указание проблемной области;
3. rescue-разбор с эталонным diff.

Если сессия приблизилась к 60 минутам, rescue-разбор позволяет закрыть её в зелёном состоянии. Самостоятельное повторение оформляется новой карточкой и не оставляет текущую незавершённой.

Подсказки раскрывает `pnpm session:hint`: команда не принимает номер, показывает
только следующий уровень и сохраняет его в локальном progress. Их исходники,
quiz keys и reference solutions находятся в отдельном Git ref `course-support`,
а не в рабочем дереве основной ветки. Это исключает случайный спойлер при
обычной навигации по проекту; владелец локального repository технически может
прочитать ref намеренно.

## Метаданные

Каноническая карта находится в `course.json`. Порядок сессий внутри раздела задаёт зависимости по умолчанию: каждая следующая сессия доступна после предыдущей. Первый шаг раздела зависит от последнего шага предыдущего раздела.

Поля сессии:

- `id` — стабильный идентификатор;
- `title` — короткое название результата;
- `minutes` — ожидаемая длительность от 30 до 60 минут;
- `kind` — тип учебной работы;
- `outcome` — что будет уметь или понимать учащийся;
- `done` — проверяемое условие завершения;
- `checks` — обязательные автоматические или ручные проверки.

Допустимые типы работы: `observe`, `complete`, `debug`, `build`, `refactor`, `compare`, `test`, `integrate`, `review`, `ship`.

## Прогресс

Runner должен хранить локальный прогресс вне Git и разрешать только одну активную сессию. Планируемый интерфейс:

- `pnpm session:next` — показать следующую доступную карточку;
- `pnpm session:start <id>` — подготовить её starter и записать активную сессию;
- `pnpm session:check` — выполнить обязательные проверки;
- `pnpm session:review` — собрать task, rubric, diff и результаты проверок для
  Codex; команда сама не запускает агента;
- `pnpm session:hint` — раскрыть только следующий уровень помощи;
- `pnpm session:finish` — проверить `DONE`, сохранить checkpoint и закрыть карточку.

`session:check` всегда локальный и автоматический. Если manifest содержит label
`review`, завершение дополнительно требует актуального вердикта Codex,
записанного через `session:review --record PASS|NEEDS_WORK`.
